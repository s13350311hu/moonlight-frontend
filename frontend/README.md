# 行間

寫小說用的本地優先編輯器。離線可用，多裝置同步。

四種東西掛在同一副骨架上：章節樹、設定集、伏筆表、素材庫。另外兩個面板是方法——
大塚英志《物語の体操》的方程式，和七十八張字卡。

## 跑起來

```bash
npm install
npm run dev     # http://localhost:5275
```

線上版：https://hangjian-tsuki7.vercel.app

## 同步

雲端跟 LifeGrid **共用同一個 Supabase 專案的同一張 `records` 表**，所以：

- 填一樣的專案網址和 anon key，登一樣的帳號。
- 行間的資料 `tbl` 一律掛 `hj_` 前綴（`hj_chapters`、`hj_entries`…）。LifeGrid 拉取時
  會跳過它不認得的 `tbl`（見它 `syncEngine.ts` 的 `applyRemote`），兩邊不會互相干擾。
  **新增資料表時前綴不能拿掉**，否則 `hj_chapters` 會撞上 LifeGrid 自己的 `chapters`。
- 不用另外跑 SQL。表和 `server_seq` 觸發器都是 LifeGrid 那份 schema 建好的。

設定的地方在右側「同步」面板。網址和 key 存在這個瀏覽器的 localStorage，
也可以改用 Vercel 環境變數 `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` 烤進 build。

同步策略照抄 LifeGrid：

- 每筆資料帶 `updatedAt` / `deleted` / `dirty`，衝突用 last-write-wins。
- 推送：`dirty=1` 的列 upsert 上去，推完清掉 dirty（推送期間又被改過的不清）。
- 拉取：抓 `server_seq > 游標` 的列。**游標用伺服器序號，不是時間戳**——
  兩台裝置時鐘差幾秒的話，慢的那台寫的東西會低於已推進的游標，那筆就永遠拉不到。
- 刪除是軟刪除。真的刪掉的話，其他裝置不會知道這筆消失了。

## 六個面板

| 面板 | 做什麼 |
|---|---|
| **抽卡** | 兩種用法。「接下一場」抽三張，站在推力、阻力、代價上。「用卡牌寫故事」發六張排成書上圖 6 的十字牌陣：1 主角的現在、2 近未來、3 過去、4 援助者、5 敵對者、6 結局（目的）。每個位置寫一句它在你故事裡是什麼，再把六張接成一則故事，存起來、存成素材，或接進稿子 |
| **方程式** | 格雷馬斯的六個行為項 ＋ 普羅普的三十一機能掛到章節上。附七種登場人物與描寫判準 |
| **設定集** | 角色、地點、物件、設定。填了別名之後，內文一提到就會亮起來 |
| **伏筆** | 埋在哪、要在哪回收、回收了沒。未回收的排最前面 |
| **素材** | 靈感筆記，內容和來源都可以改。搜尋會同時翻全稿，標出第幾章 |
| **備份** | 匯出全稿 Markdown 或完整 JSON，也可以從 JSON 還原 |

## 方法從哪來

- **字卡**：《物語の体操》第一講。內田伸子的實驗——幾張卡擺在小孩面前就能講出故事，
  中途插一張毫不相干的，他照樣接得下去。編故事不是等靈感，是把不相干的東西接起來的技術。
  所以卡面上只有詞，不指涉任何東西；接的時候不要問它象徵什麼，問它在這一場裡具體是什麼。
  「用卡牌寫故事」用的是同一講圖 6 的六張牌陣（現在／近未來／過去／援助者／敵對者／結局），
  書上的排法是十字：3 在最上、1 在其下、5-2-4 橫排、6 在最下。「插一張不相干的」是實驗裡那台直升機。
- **方程式**：《物語の体操》第三講。格雷馬斯的行為者模型（主體／對象／送出者／接收者／
  援助者／敵對者）＋ 普羅普的三十一個機能與七種登場人物的行為領域。
- **描寫判準**：《小説作法ABC》第六章「描写／速度／比喩」。小說由會話・描寫・說明構成；
  描寫的細分化；描寫的速度（視點人物移動得多快，決定他看得見多少）；比喻。
  狀態列那個「會話 X%」就是對照第一條用的。

## 介面語言

中文／日文雙語，切換在「版面（組版）」面板最上面，選擇存在本機、不同步。
第一次打開時看 `navigator.language` 決定預設。

做法是 `src/lib/i18n.ts` 的 `L(zh, ja)`：**翻譯就寫在用到它的地方**，不做 key 對照表——
那樣要維護兩份檔案，而且會出現「某個 key 忘了翻」這種只有執行到才發現的錯。
`L()` 讀的是模組層級的語言狀態，`App.tsx` 裡呼叫一次 `useLang()`，語言一變整棵樹跟著重畫。

方法用語（三十一機能、六個行為項、七種登場人物、描寫判準）在 `src/lib/propp.ts` 裡
各自帶中日兩份，日文用的是原書的詞。中文介面會在術語旁邊附上日文原詞，日文介面不重複。

## 輸入法

**內容區的 DOM 由 ProseMirror 自己管**，React 不會重繪到它，組字不受影響。
換章節時用 `setContent(html, { emitUpdate: false })`，而且**有焦點時絕不換內容**
（`Editor.tsx` 的那個 effect），不然打到一半會被抽掉。
狀態列的字數和會話比例直接寫 DOM，不走 state，打字時整棵 React 樹都不重繪。

面板裡的文字輸入走 `src/components/Field.tsx` 的 `TextInput` / `TextArea`。
**不要改回 React 的受控寫法**（`value` + `onChange`）：注音、日文這類要組字的輸入法，
在組字途中如果外面把 `value` 再塞回去一次，組字就會被打斷，畫面上只剩下沒選字的注音。
所以值交給 DOM 自己管，只有在「外面的值變了、而且使用者沒在打這一格」時才覆蓋，
並且組字途中（`compositionstart` 到 `compositionend` 之間）不送出變更。

同理，`useLiveQuery` 在重新查詢的空檔會回 `undefined`，直接照它渲染會讓畫面掉回
「載入中」、把編輯區卸載重建。`App.tsx` 的 `useSticky` 就是擋這件事的。
